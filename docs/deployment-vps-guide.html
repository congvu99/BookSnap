Dựng VPS Contabo cho nhiều dự án

Docker Compose + Caddy (HTTPS tự động), BookSnap là dự án đầu tiên. Mỗi lệnh có ghi chạy ở đâu, ý nghĩa và cách kiểm tra. Làm lần lượt từ trên xuống; lần đầu mất ~2–3 giờ, mỗi dự án sau ~15 phút.

Thông số của bạn

Điền vào đây, mọi lệnh bên dưới tự cập nhật (tô vàng). Chỉ lưu trong trình duyệt này.

Nhãn trên mỗi khối lệnh WINDOWS chạy trên máy tính của bạn (cmd/PowerShell) · SERVER chạy trong phiên SSH trên VPS · FILE nội dung một file.

1SSH bằng key (không phải gõ mật khẩu)

SSH key gồm 2 file: khoá riêng (giữ trên máy bạn, như chìa khoá) và khoá công khai (đặt lên server, như ổ khoá). An toàn hơn mật khẩu và không phải gõ lại.

Windows
ssh-keygen -t ed25519 -C "may-windows"
  • -t ed25519: loại key hiện đại, ngắn, an toàn.
  • -C: ghi chú để sau này nhận ra key của máy nào.
  • Hỏi đường dẫn: Enter (mặc định C:\Users\<bạn>\.ssh\id_ed25519). Hỏi passphrase: Enter bỏ trống, hoặc đặt để bảo vệ key nếu máy bị lộ.
Windows (cmd)
type %USERPROFILE%\.ssh\id_ed25519.pub | ssh root@ "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
  • Đọc khoá công khai (.pub) rồi gửi qua SSH, nối vào ~/.ssh/authorized_keys của root = danh sách key được phép vào.
  • chmod 700 / 600: chỉ chủ sở hữu đọc được; sshd từ chối key nếu quyền quá rộng.
  • Đây là lần cuối gõ mật khẩu root. Tắt Unikey, dán bằng chuột phải.

2Bảo mật server

Vì sao làm ngayLog cho thấy VPS mới 45 phút đã bị bot dò mật khẩu root từ nhiều IP. Mật khẩu root cũ cũng đã bị lộ trong chat → đổi ngay.

2.1 Đổi mật khẩu, cập nhật hệ thống

Server (root)
passwd
timedatectl set-timezone Asia/Ho_Chi_Minh
apt update && apt -y full-upgrade
apt -y install git curl ufw fail2ban python3-systemd htop
[ -f /var/run/reboot-required ] && reboot
  • passwd: đặt mật khẩu root mới (dùng khi cần vào qua VNC Contabo).
  • timedatectl: giờ Việt Nam → log và lịch backup dễ đọc.
  • apt update: tải danh sách gói mới; full-upgrade: cài bản vá bảo mật.
  • ufw firewall, fail2ban chặn IP dò mật khẩu, htop xem CPU/RAM.
  • Dòng cuối: nếu kernel vừa cập nhật thì khởi động lại (đợi ~1 phút rồi ssh vps-root lại).

2.2 Tạo user deploy (không làm việc hằng ngày bằng root)

Server (root)
adduser deploy
usermod -aG sudo deploy
install -d -m 700 -o deploy -g deploy /home/deploy/.ssh
install -m 600 -o deploy -g deploy /root/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
  • adduser: tạo user, hỏi mật khẩu (dùng cho sudo), các câu còn lại Enter.
  • usermod -aG sudo: cho phép chạy lệnh quản trị bằng sudo.
  • install: tạo thư mục/copy file và đặt đúng chủ + quyền trong 1 lệnh → user deploy dùng chung key của bạn.
Kiểm tra (cửa sổ Windows mới)ssh vps vào được, rồi chạy sudo whoami → in ra root.

2.3 Firewall

Server
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw --force enable
sudo ufw status verbose
  • Mặc định chặn mọi kết nối vào, chỉ mở: SSH (22), HTTP (80, cần để Let's Encrypt xác minh + chuyển sang HTTPS), HTTPS (443 tcp, và udp cho HTTP/3).
  • Phải allow OpenSSH trước enable, nếu không tự khoá mình ngoài.

2.4 fail2ban: chặn IP dò mật khẩu

Server
sudo tee /etc/fail2ban/jail.local >/dev/null <<'EOF'
[sshd]
enabled  = true
backend  = systemd
maxretry = 5
findtime = 10m
bantime  = 1h
EOF
sudo systemctl enable --now fail2ban
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd
  • tee … <<'EOF' … EOF: ghi đoạn chữ ở giữa vào file (cách tạo file không cần mở trình soạn thảo). Dùng lại nhiều lần trong hướng dẫn này.
  • Sai 5 lần trong 10 phút → IP bị chặn 1 giờ. backend = systemd: Ubuntu 24.04 ghi log SSH vào journal.

2.5 Tắt đăng nhập bằng mật khẩu và root qua SSH

Giữ phiên SSH hiện tại mởChỉ đóng sau khi đã thử đăng nhập được ở cửa sổ mới. Nếu lỡ khoá: Contabo panel → VNC → đăng nhập root bằng mật khẩu → xoá file dưới đây → systemctl restart ssh.
Server
sudo tee /etc/ssh/sshd_config.d/00-hardening.conf >/dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
EOF
sudo sshd -t && sudo systemctl restart ssh
sudo sshd -T | grep -Ei '^(permitrootlogin|passwordauthentication)'
  • Tên bắt đầu 00-: sshd lấy giá trị đầu tiên đọc được, file này được đọc trước 50-cloud-init.conf (file Contabo bật mật khẩu).
  • sshd -t: kiểm tra cú pháp trước khi restart (sai thì không restart).
  • Kết quả mong đợi: permitrootlogin no, passwordauthentication no.
Kiểm tra (cửa sổ Windows mới)ssh vps vào được. ssh vps-root bị từ chối là đúng. Từ giờ dùng ssh vps + sudo.

2.6 Swap và tự cài bản vá

Server
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
sudo dpkg-reconfigure -plow unattended-upgrades
  • Swap = RAM dự phòng trên đĩa. VPS chưa có swap; khi build image hoặc nhiều dự án chạy cùng lúc, thiếu RAM sẽ bị kernel giết tiến trình (OOM). Dòng /etc/fstab giữ swap sau khi reboot.
  • unattended-upgrades: chọn Yes → tự cài bản vá bảo mật hằng ngày.

3Cài Docker

Server
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt update
sudo apt -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
  • Thêm kho phần mềm chính thức của Docker (bản trong Ubuntu thường cũ) + khoá GPG để apt xác minh gói không bị giả mạo.
  • docker-compose-plugin: lệnh docker compose (có dấu cách, bản v2).
Server
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
EOF
sudo systemctl restart docker
sudo usermod -aG docker deploy
exit
  • daemon.json: giới hạn log mỗi container 3 file × 10 MB. Không đặt thì log phình đến đầy ổ đĩa.
  • usermod -aG docker: user deploy chạy docker không cần sudo. exit rồi ssh vps lại để quyền có hiệu lực.
Bảo mậtNhóm docker ≈ quyền root. Chỉ thêm user bạn tin tưởng.
Bẫy lớn: Docker bỏ qua ufwCổng khai báo ports: trong compose được Docker mở thẳng ra Internet, ufw không chặn. Quy tắc cho server này: chỉ Caddy được có ports:. App/DB khác không khai báo ports:; nếu cần thử nghiệm thì "127.0.0.1:8000:8000" (chỉ trong máy).
Kiểm tradocker run --rm hello-world in "Hello from Docker!". docker compose version in phiên bản v2.

4Tên miền miễn phí DuckDNS

Let's Encrypt chỉ cấp chứng chỉ HTTPS cho tên miền. DuckDNS cho tên miền miễn phí dạng ten.duckdns.org, và tự trỏ mọi tên con (booksnap.ten.duckdns.org, app2.ten.duckdns.org…) về cùng IP → mỗi dự án một tên con, không cần đăng ký thêm.

  1. Vào duckdns.org → đăng nhập bằng GitHub/Google.
  2. Ô sub domain: gõ tên (vd congvu) → add domain.
  3. Ô current ip của tên vừa tạo: điền → update ip.
  4. Điền domain đầy đủ vào ô "Domain gốc" ở đầu trang.
Windows
nslookup booksnap.
Kiểm traDòng Address: cuối cùng = . Nếu chưa đúng, đợi 1–5 phút.
Giới hạnDuckDNS là dịch vụ miễn phí do cá nhân vận hành, nếu ngừng thì web không vào được. Khi dùng thật lâu dài, mua domain riêng (~250k/năm), tạo bản ghi A (và *) trỏ về IP, rồi chỉ đổi tên miền trong các file .caddy. Phương án tạm khác: booksnap.62-171-135-240.sslip.io (không cần đăng ký, nhưng có thể dính giới hạn cấp chứng chỉ chung của Let's Encrypt).

5Caddy dùng chung + HTTPS tự động

5.1 Thư mục và mạng chung

Server
sudo mkdir -p /srv/caddy/conf/sites /srv/apps /srv/sites /srv/backups
sudo chown -R deploy:deploy /srv
docker network create web
  • chown: user deploy làm chủ /srv → không cần sudo khi làm việc với dự án.
  • docker network create web: tạo mạng chung 1 lần; Caddy và mọi app sẽ nối vào.

5.2 File compose của Caddy

Server
cat > /srv/caddy/compose.yml <<'EOF'
name: caddy
services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp"
    volumes:
      - ./conf:/etc/caddy:ro
      - /srv/sites:/srv/sites:ro
      - caddy_data:/data
      - caddy_config:/config
    networks: [web]
volumes:
  caddy_data:
  caddy_config:
networks:
  web:
    external: true
EOF
  • image: caddy:2: bản Caddy chính thức, bản 2.x mới nhất.
  • restart: unless-stopped: tự chạy lại khi crash hoặc server reboot.
  • ports: container duy nhất mở cổng ra Internet.
  • ./conf:/etc/caddy:ro: cấu hình nằm ở /srv/caddy/conf, container chỉ đọc (ro).
  • caddy_data: nơi lưu chứng chỉ HTTPS. Không được xoá, nếu mất Caddy phải xin lại (dễ dính giới hạn Let's Encrypt).
  • external: true: dùng mạng web đã tạo ở 5.1, không tự tạo mạng riêng.

5.3 Caddyfile chung + trang thử

Server
cat > /srv/caddy/conf/Caddyfile <<'EOF'
{
	email 
}

import /etc/caddy/sites/*.caddy
EOF

cat > /srv/caddy/conf/sites/hello.caddy <<'EOF'
hello. {
	respond "Caddy OK - HTTPS hoat dong"
}
EOF

cd /srv/caddy && docker compose up -d && docker compose logs -f
  • email: Let's Encrypt gửi cảnh báo nếu chứng chỉ sắp hết hạn mà không gia hạn được.
  • import …/*.caddy: mỗi dự án 1 file riêng trong sites/ → thêm/xoá dự án không đụng file chung.
  • Trang hello: kiểm tra HTTPS chạy trước khi có app. Chỉ cần viết tên miền, Caddy tự xin chứng chỉ, tự chuyển http → https, tự gia hạn trước khi hết hạn 90 ngày.
  • logs -f: xem log trực tiếp; thấy certificate obtained successfully là xong. Ctrl+C để thoát (Caddy vẫn chạy).
Kiểm traMở https://hello. trên trình duyệt → thấy "Caddy OK", có ổ khoá. Xong thì xoá trang thử ở 6.4.

5.4 Lệnh Caddy hay dùng

6.4 Gắn tên miền

Server

booksnap. {
	encode zstd gzip
	reverse_proxy booksnap:8000
}
EOF

cd /srv/caddy && docker compose exec -w /etc/caddy caddy caddy reload

11.3 Workflow

.github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]
  workflow_dispatch:

concurrency:
  group: deploy-booksnap
  cancel-in-progress: false

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements-dev.txt
      - run: python -m pytest -q

  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - name: Deploy over SSH
        env:
          SSH_KEY: ${{ secrets.VPS_SSH_KEY }}
          KNOWN_HOSTS: ${{ secrets.VPS_KNOWN_HOSTS }}
          HOST: ${{ secrets.VPS_HOST }}
        run: |
          install -m 700 -d ~/.ssh
          printf '%s\n' "$SSH_KEY" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          printf '%s\n' "$KNOWN_HOSTS" > ~/.ssh/known_hosts
          ssh -o BatchMode=yes "deploy@$HOST"
  • concurrency: 2 lần push liền nhau thì deploy lần lượt, không chạy chồng lên nhau.
  • needs: test: test đỏ thì không deploy.
  • Dùng ssh có sẵn thay vì action của bên thứ ba → ít rủi ro chuỗi cung ứng.
  • Xem kết quả: tab Actions của repo. Chạy tay: Actions → Deploy → Run workflow.
